## Cache in the database
- [x] Clean up by the size of the database: `DATABASE_MAX_MB` (default 1024 = 1 GB); after data was fetched and added (and no fetch runs) the size is checked; when it is bigger, the data used longest ago is deleted and the database compacted (`community_insights/cleanup.py`)
- [x] `DATABASE_MIN_AGE_HOURS` (24): the latest fetched or used data is never deleted for space; if only such data is left, a warning in the log and on the cache page
- [x] Little overhead: the check only runs when the queue is empty; the used size is measured without compacting; shrinking goes 10 % below the limit; one compaction at the end; when only young data is left, no new try until the first data is old enough
- [x] The totals of the estimate are kept for 10 minutes: reloading the fetch page does not ask GitHub again
- [x] Interrupted fetches continue where they stopped, so few requests are made again (`Repository.resume`, saved after each page)
- [x] Models for repositories, pull requests, issues, events and people
- [x] `created`, `fetched_at` and `last_used_at` on every cached object
- [x] Cache page: a timeline, oldest use first, with delete buttons

- [x] Incremental sync (only items changed since the last sync)
